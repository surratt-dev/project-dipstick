# Design: 271-audit-log-reader-structural-test (#271)

*Revised by Ingrid Sollenberger (Solution Architect) after `design-review-engineer.md` (B1-B3) and `design-review-security.md` (B-1, B-2, B-3, P-4, spec wording, D-5 wording, fail-closed gaps). Section "Review resolution" at the end records what was adopted, rejected and deferred, with reasons.*

## Context

Writers to `audit_log` are many and out of scope. Readers today: R1 `routes/content.ts#fetchConnectionRecoveries` (flat SELECT, equality on `session.connection_recovered`, plus `metadata->>'scopeId' = $1`; facilitator via session history); R2/R3 `sessions/default-topic-maintenance.ts#readTemplateList` (two statements: the change query binds `a.operation = ANY($2::text[])` with the constant `MAINTENANCE_AUDIT_OPERATIONS` passed as a **bound parameter**, the SQL has no `${}`; the reorder query uses literal equality); R4 `#readTemplateHistory` (`= ANY($2::text[])`, also a bound parameter). R2 to R4 serve `application_admin` only, and both functions are exported and called only from `routes/admin-default-topics.ts`. The issue's "the one reader" means the one non-admin reader, not the only reader. Cite functions, not line numbers (the issue's L1115 has drifted).

Writers: about 45 column-listed `INSERT INTO audit_log (cols)` sites, almost all `VALUES`, many with a newline between the table name and `(`. One is an INSERT...SELECT: `auth/fail-open-topic-audit.ts` `FAIL_OPEN_TOPIC_AUDIT_INSERT_SQL` (module-level const, enclosing key `<module>`, `... SELECT $1::uuid, ... FROM (SELECT 1) s LEFT JOIN users u ...`). It is a writer and must produce no finding.

House style: `template-writer-structural.test.ts` with `helpers/template-writer-scanner.ts` (TypeScript compiler API, function-keyed allow-list, stale check, can-fail self-tests) and `team-not-found-envelope-structural.test.ts` (small, `productionSources()`).

## Decisions

**D1. Inventory-style, not exceptions-only.** Every touch is listed, even a compliant one. A new correctly filtered reader that serves participants of an admin-visible operation must not sail through; friction on a rare, significant event is the point. (The issue says "allow-list"; this is a deliberate, recorded deviation.)

**D2. Vocabulary: writer, touch, tripwire.** All matching is over the *resolved* SQL text (D5) after the SQL tokenizer (D4a) has stripped comments and blanked string contents, so prose inside a comment or a quoted string value never counts as table syntax.

- *Table position*: a token `audit_log` whose previous significant token is one of `FROM`, `JOIN`, `INTO`, `UPDATE`, `TRUNCATE`, `TABLE`, `ONLY`, `COPY`, `MERGE`, `LOCK`, or a `,` inside a FROM list (`FROM users u, audit_log a`). The token is whole-word (`audit_logs` and `audit_log_archive` do not match), optionally `public.`-qualified, optionally double-quoted. Unquoted match is case-insensitive (`AUDIT_LOG` reads the table); quoted match is exact lowercase only (`"AUDIT_LOG"` is a different table and is not a touch, but it still trips the tripwire below). Arbitrary whitespace and newlines are allowed between tokens.
- *Writer*: a literal whose only table-position use of `audit_log` is the target of `INSERT INTO audit_log (<column list>)`, whose row source is `VALUES` **or a SELECT that does not itself reference `audit_log` in a table position**, with any `ON CONFLICT` or `RETURNING` tail. A writer is not a touch. The fail-open INSERT...SELECT above is a writer. `INSERT INTO audit_log (cols) SELECT ... FROM audit_log` is a touch (a self-read).
- *Touch*: a literal with `audit_log` in table position that is not a writer. This covers SELECT, JOIN, subquery, CTE, INSERT with no column list, self-reading INSERT...SELECT, UPDATE, DELETE, TRUNCATE, COPY, TABLE, MERGE, LOCK and `ONLY`/schema-qualified/quoted forms. The pass condition for writers is "all production writers produce zero findings", not "all VALUES writers".
- *Tripwire* (fail-closed, B-2.3): any string literal, template chunk, identifier or property name in non-comment code that contains `audit_log` as a whole word (case-insensitive) and is neither part of a recognised touch nor a writer is itself a finding, `tripwire`, and it is **not inventoriable**. It catches `const TABLE = "audit_log"`, arrays of table names, `format('%I', 'audit_log')` and error-message prose. The fix for prose is to reword ("audit log write failed"); the failure message says so. This is a deliberate reconciliation of the two reviews: Marcus asked that prose not force a scanner hack, Tomás asked that no stray `audit_log` string pass silently. The tripwire costs nothing today (the only non-SQL matches are comments, which the scanner ignores) and a reworded message is a one-word fix, so it is not a false-positive trap.
- Classes: `exact-match` and `admin-only`. UPDATE, DELETE, TRUNCATE, COPY, MERGE, LOCK and any other non-read verb have no class and fail as unclassifiable (no `mutator` class: no current entry, add one by reviewed change if ever needed).

**D3. What the test enforces (the honest guarantee).** Every touch is inventoried; every `exact-match` statement passes the positive grammar (D4) and avoids protected operations (D6); `admin-only` entries are trusted on their reason for *what the statements return and whom the route serves*, but verified for **who may call the function** (D4c) and **how many statements it holds** (D4d). The test cannot decide who a query serves; the Security Analyst reviews that classification by convention. Reason quality beyond non-blank is human review by decision.

Per-entry semantics, stated so nobody over-reads the inventory: every `audit_log`-touching literal in an `exact-match` function must pass independently (the judge runs per statement, not per entry). A function that mixes shapes is `admin-only` as a whole, and then none of its statements is checked: R2 holds one `= ANY` and one literal-equality statement, so `readTemplateList` is `admin-only` and the reorder statement (R3) is **not** verified by the test, even though it would pass alone. Protected-value checks (D6) run only on `exact-match`, not on `admin-only`.

**D4. `exact-match` is a positive grammar over a small SQL tokenizer.** There is no SQL parser in the repo and none is added. The only accepted form is defined; everything else fails closed as unclassifiable. This replaces the earlier blacklist of bad forms, which leaks the first form nobody listed.

*D4a. Tokenizer (about 150 lines with the clause splitter; this is the bulk of the work).* Input is the resolved literal text. It strips `--` line comments and `/* */` block comments (nested block comments fail), consumes single-quoted strings with `''` escapes, and double-quoted identifiers with `""` escapes; strings are emitted as one opaque `STRING(value)` token so keywords and parentheses inside them never count. It emits identifiers, `$n` parameters, numbers, operators (including `->>`, `::`) and parens, tracking paren depth per token. Any `E'...'`, `U&'...'`, dollar-quote (`$$` or `$tag$`), `;` (multi-statement), unterminated string or comment makes an `exact-match` statement unclassifiable. (Tokenizing `admin-only` and touch-detection text uses the same tokenizer for comment/quote stripping; an unterminated string there is also unclassifiable.)

*D4b. Positive grammar for one `exact-match` statement:*
1. Exactly one statement, first token `SELECT`, with exactly one `SELECT` token in total (no subquery, CTE or scalar subquery), and none of the tokens `WITH`, `UNION`, `INTERSECT`, `EXCEPT`, `LATERAL`, `JOIN`, `BETWEEN` anywhere, and no `,` between FROM sources. In words: one flat `SELECT ... FROM audit_log [AS] [alias] WHERE ...` over a single table. Because there is one table, `operation` cannot bind to another table (alias binding, B-3, is removed by construction). A JOIN reader is unclassifiable and goes to the `admin-only` conversation or a reviewed grammar extension.
2. The FROM source is `audit_log` in table position (D2 forms), optionally followed by `[AS] alias`.
3. The WHERE clause runs at depth 0 from `WHERE` to the first of `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT`, `OFFSET`, `FOR`, `FETCH`, `WINDOW`, end. Split it into conjuncts on depth-0 `AND`. **No depth-0 `OR` anywhere in the WHERE.** Parenthesised sub-expressions are legal only as part of a different conjunct (e.g. `AND (metadata->>'k' = 'a' OR metadata->>'k' = 'b')`), never as the operation or scope conjunct.
4. **Exactly one** conjunct mentions the identifier `operation` (unquoted any case, or `"operation"`, optionally qualified by the table name or its alias), and that conjunct is, token for token, `[qual.]operation = STRING` with nothing else: no cast (`'x'::text` fails), no parentheses (`('x')` fails), no function wrapper, no `$n`, no literal on the left, no `IN ('x')`, no `= ANY(ARRAY['x'])`, no `IS NOT DISTINCT FROM`, no `<>`/`!=`, no `LIKE`/`ILIKE`/`SIMILAR TO`/`~`/`^@`, no `NOT`. A second mention of `operation` in any other conjunct fails. `operation` in the SELECT list, ORDER BY or elsewhere is irrelevant; the WHERE conjunct list is what is judged. A developer's first instinct is `IN ('x')`; the failure message names the accepted form `operation = 'x'` explicitly.
5. **Row scope (P-4).** At least one other conjunct is, token for token, `[qual.]team_id = <STRING | $n | number>` or `[qual.]metadata ->> 'scopeId' = <STRING | $n>`. This blocks the copy-pasted-without-scope reader that would return every team's rows to any facilitator. It checks presence, not correctness, of the scope predicate (see Known limits). There is no "global reader" flag: a legitimately global non-admin reader is unclassifiable today and gets a reviewed grammar extension if one ever exists.
6. `operation = '<lit>'` where the literal is a protected operation fails (D6).

Fixtures: one per distinct row of the grammar, positive and negative, table-driven (`it.each`). Required cases include, for comment/quote handling: `WHERE operation = 'x' -- AND team_id = $1` (scope absent, fails), `/* OR */` between conjuncts (passes, comment stripped), `metadata->>'k' = 'a OR b'` and `'('` inside a string (string opaque, passes where otherwise valid), `E'x'`, `U&'x'`, `$$x$$` (unclassifiable); a comment containing a forged `operation = 'session.x'` predicate when the real one is missing (fails); `(operation = 'x' OR true)`; `EXISTS (SELECT 1 ... operation = 'x')`; `UNION` with one correct and one unfiltered branch; CTE and subquery readers; `x.operation = 'ok'` on a JOIN; `;`-separated statements.

*D4c. Caller check for `admin-only` (B-1).* Each `admin-only` entry carries `callers: string[]`, the files (relative to `packages/backend/src`, production only) allowed to reference the function. The scanner walks every production file and flags any `Identifier`, import specifier name (including `as` aliases), export specifier or property-access name equal to the function's name that appears in a file other than the defining file and `callers`. Namespace imports (`m.readTemplateList`) and barrel re-exports are caught by the property/export-specifier match. Today `readTemplateList` and `readTemplateHistory` are called from `routes/admin-default-topics.ts` (and `readTemplateList` internally in the defining module), so `callers: ["routes/admin-default-topics.ts"]`. *Amendment (Security X-1/X-2):* string-literal element access (`m["readTemplateList"]`) also counts as a reference. Exported functions of the defining file that reach the admin-only function (directly, or via same-file helpers) are "wrappers": each must be listed in the entry's `wrappers` (today `writeTemplateTopics` for `readTemplateList`), and importers of a wrapper count as importers of the reader. Not followed: wrappers in another file, computed keys, `Reflect`/`eval`. *Deviation:* the judge requires exactly one caller file, not a list of any length (stricter, safer; relax if a second admin caller is ever legitimate). This is name-based, so it can over-report on a name collision; the remedy is a rename, not an inventory edit. Justification, cheapest sound option: the reuse-of-an-exempt-function path is the one abuse the review identified where the exemption silently outlives its premise (the function was admin-only *because* of its call site), a few dozen lines on the existing AST walk, and it fails closed. A mechanical check that the caller file really enforces `application_admin` is **not** adopted: a string search for the role matches comments and is theatre; a real check needs route-level analysis (see Review resolution).

*D4d. Statement count and class by structure (admin-abuse mitigations).* Each `admin-only` entry carries `statements: N` (the number of touching literals in the function). A new or split statement inside an `admin-only` function changes N and fails until the entry is edited, which puts the new SQL in front of a reviewer. A statement fingerprint (hash of normalised SQL) is **rejected**: every legitimate edit of R2/R4 SQL would churn it, and the count already catches the abuse that matters (an added statement). Honest residual: an *edit in place* to an existing admin-only statement is not detected. The class snapshot is achieved structurally and for free: the inventory is two separate objects, `EXACT_MATCH` and `ADMIN_ONLY`, and `admin-only` entries require the extra fields `callers` and `statements`, so reclassifying `exact-match` to `admin-only` is never a one-word change; it is a move between blocks plus two new fields.

**D5. Resolution of SQL text, and unclassifiable statements.** Before touch detection and grammar judgement the scanner builds the literal's text and **substitutes** every `${CONST}` that refers to a same-file `const` initialised with a string literal or a no-substitution (or recursively resolvable) template literal. The substituted text is what gets tokenized; the constant's own definition literal is also scanned (so a constant holding `FROM audit_log` is caught at its definition and, if a template includes it, in the template). Unresolved substitutions: a `${}` that is a function call, a property access, an import, a parameter, a `let`, or any other non-constant is **unresolved**. An unresolved substitution in table position (directly after `FROM`, `JOIN`, `INTO`, `UPDATE`, `TRUNCATE`, `COPY`, `TABLE`, `ONLY`, `LOCK`, `MERGE`, or a FROM-list comma) in a SQL-looking literal fails as unclassifiable (positive trigger, B-2.2). A literal is *SQL-looking* when, after stripping leading whitespace and comments, it begins with `SELECT`, `WITH`, `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `COPY`, `TABLE`, `MERGE` or `LOCK` (case-insensitive). A SQL-looking literal that is an operand of `+` or the receiver or argument of `.concat(`, or that is a tagged template, fails as unclassifiable. Placeholders `$1` are plain text and never substitutions. Unresolved substitutions **outside** table position (for example the existing `${JOIN_LINK_ACTIVE_SQL}`) are allowed: no cross-file resolution is built.

*Imported SQL fragments (B-2.2) and why no cross-file resolution:* detection is per literal **at the literal's definition**. A fragment that spells `audit_log` is scanned where it is defined; it is a touch there and, being a fragment (no `SELECT ... FROM` shape), cannot satisfy the `exact-match` grammar, so it is unclassifiable and must be reviewed as `admin-only`. A fragment that does not spell `audit_log` cannot be seen (blind spot, see Known limits). This is cheaper than resolving imports and fails closed for every case the scanner can see.

Dropped from the earlier D5: clause (c), "SQL passed from an identifier that does not resolve to a literal" (unimplementable: call arguments are not typed as SQL, and every `.query(IDENTIFIER, ...)` site's literal is scanned at its definition anyway), and clause (b), a `$n`-placeholder clause (placeholders are not substitutions). The earlier claim that `${MAINTENANCE_AUDIT_OPERATIONS}` interpolation motivates the same-file-constant pass case was wrong (R2/R4 bind it as a parameter); the pass fixture stays, with a synthetic constant, and R2 is not cited for it. Fixtures: constant containing `audit_log` (touch), constant holding an operation value used inline (resolved before judgement), unresolved import in table position (fail), unresolved substitution outside table position (pass), `+` concat of SQL-looking literals (fail), tagged template (fail), `AUDIT_LOG` and `Audit_Log` (touch), `"AUDIT_LOG"` (tripwire), `public.audit_log`, `FROM ONLY audit_log`, `COPY audit_log TO`, `TABLE audit_log`, `LOCK TABLE audit_log`, comma join, `audit_logs` and `audit_log_archive` (no finding), prose string `"audit_log write failed"` (tripwire), comment-only mention (no finding), the fail-open INSERT...SELECT shape (writer, no finding), `INSERT INTO audit_log (cols) SELECT ... FROM audit_log` (touch), `INSERT INTO\n  audit_log\n  (cols)` multi-line (writer), column-listed INSERT with `ON CONFLICT` and with `RETURNING` (writer).

**D6. Protected set** is a short constant taken from the "Audit visibility guard" sentence and widened to fail closed: operations beginning `admin.` (case-sensitive; the bare `admin.` counts), operations beginning `topic.config_` (covers `topic.config_list_denied` and any future sibling denial row; P-1), plus the exact names `topic.config_list_denied` and `admin.topic_config_accessed` (redundant with the prefixes, kept so the spec's named values appear verbatim in the code). Near-misses `topic.configure` and bare `admin` pass (they match nothing today). The header cites the requirement by name. Fixtures: each named value, `admin.x`, `admin.`, `topic.config_x`, near-miss `topic.configure` (pass). The check runs on `exact-match` only.

**D7. AST scanner for TypeScript, tokenizer for SQL.** The TypeScript compiler API is required because the inventory key is the enclosing function and comments must be ignored. Scanned root: `packages/backend/src` via `productionSources()`, named in the header. Placed at `routes/__tests__/helpers/audit-log-reader-scanner.ts`. **Shared helpers are exported, not copied:** add `export` to `literalText`, `functionLabel` and `enclosingFunction` in `template-writer-scanner.ts` (zero behaviour change; its existing tests still guard it). Keys follow its labels, including `<module>` and `route GET /x`, both legal inventory keys, documented in the header. Anonymous functions, arrow functions assigned to object properties and class methods get the labels that `functionLabel` already produces; an enclosing scope with no deterministic label makes the statement unclassifiable. Two functions with the same label in one file collapse to one key: a documented limit, and the stale check keys on the (file, function) set. Prefilter on `text.includes("audit_log")` (case-insensitive) before parsing, so only about 25 files are parsed, plus any file containing a SQL-looking template with a table-position `${` (found by a cheap lowercase text prefilter on `${`).

**D8. Non-vacuity and error paths.** Assert detection of R1, R2/R3 (one entry) and R4 by file and function name, not by count. If a reader is renamed or moved, the stale and uninventoried failures both fire; the stale message says "renamed or moved?". Error paths, all throwing with the file named, never skipping: a source file with `sf.parseDiagnostics` is a failure naming the file; an empty `productionSources()` set, or a set with zero files containing `audit_log`, fails with a message about `BACKEND_SRC`; an unterminated SQL string or comment is unclassifiable. Additional standing assertions (cheap, fail closed): `packages/` contains exactly `backend`, `frontend`, `shared` (a new package must extend the scan roots deliberately, B-4/S-D5); `packages/backend/src` contains no `.js`, `.mjs`, `.cjs` or `.sql` files (the scan reads `.ts` only, B-2.6). The 5-second ceiling is not to be met by narrowing the scan (F-4).

**D9. No switch, standing.** False positives are resolved by fixing the scanner with a fixture, never by an inventory entry. The test reads its own source and the scanner's source and fails if either contains `process.env`, `.skip`, `.only`, `skipIf` or `runIf` (the patterns are assembled from fragments in the test so the assertion does not match itself). This replaces the one-off grep of task 2.5 with a standing check.

**D10. Failure messages** state the rule, why (non-admin callers must not read admin audit rows), and how to proceed, for a developer who has never heard of #208. Required substrings, asserted in self-tests: the rule name, `file#function`, `Audit visibility guard`, the test file name (where the header lives), and the relevant procedure step number. Grammar failures name the accepted form (`operation = '<name>'`, a scope conjunct). The tripwire message says to reword prose.

**D11. Spec delta** is a MODIFIED on the "Audit visibility guard" requirement (whole requirement restated, as the delta format requires). The original normative obligation ("no application query that serves a non-administrator caller SHALL ...") is **kept verbatim**; the delta adds verification wording and a link to the test, and keeps the original behavioural scenario beside a new structural one. A test provides evidence for an obligation; it does not replace it, and the spec must not be citable as "the test passes, therefore the requirement is met". Everything else is verbatim, verified by diff (task 4.4). Rules live in the test header so scanner changes do not need spec changes.

## Extension procedure (goes in the test header)

1. Decide who the new reader serves. Anyone other than an `application_admin`: write one flat `SELECT ... FROM audit_log WHERE operation = '<name>' AND <scope conjunct> ...`, a single non-protected operation and a `team_id` or `metadata->>'scopeId'` conjunct; add an `EXACT_MATCH` entry (file#function, reason: who, which operation, why it cannot expose admin rows).
2. Admin-only readers: add an `ADMIN_ONLY` entry whose reason names the constant or operation and the route's admin check, with `callers` (files allowed to reference the function) and `statements` (touching literals in it).
3. A new entry is reviewed by the Security Analyst role, by convention; the repo has no CODEOWNERS file.
4. A suspected false positive is fixed in the scanner with a fixture; do not widen the inventory. A tripwire hit on prose is fixed by rewording. Deleting a reader means deleting its entry; the stale check tells you.

## Known limits (stated in the test header)

- `admin-only` is trusted for what it returns and whom the route serves; verified for callers (by name, including string-literal keys and listed same-file wrappers; not computed keys or cross-file wrappers) and statement count. An in-place edit of an existing admin-only statement is not detected. A caller file is not checked for an actual `application_admin` guard.
- `exact-match` checks the *presence* of a scope conjunct, not that its value is the caller's scope (`team_id = $1` could be passed the wrong id), and does not check the selected columns (`SELECT *` or `actor_ip`/`actor_roles`/`metadata` leak): the follow-up issue.
- Entries are keyed by file plus function; duplicate labels in one file collapse to one key.
- Invisible readers: views, functions, triggers and policies in migrations; other packages' source (guarded only by the `packages/` list assertion); SQL assembled from fragments none of which spells `audit_log`; `.sql` files read at runtime; runtime query builders. The test guards against mistakes, not an attacker with SQL access or a migration PR.
- A production module placed under a `__tests__` directory is skipped by `productionSources()` (B-5). Low; recorded, not mitigated.
- Binding force is CI branch protection: the control is advisory unless the `test` job is a required status check on `main`. The PR states which (F-3). Approval of inventory changes is by convention (no CODEOWNERS), see Open decision.
- Runtime: pure source scan plus fixture self-tests; ceiling 5 seconds under default config, implementer reports measured time.

## Review resolution

**Adopted from Engineering:** B1 (writer definition, fail-open fixture, pass condition "all production writers"); B2 (table-position, whole-word detection, prose ignored in SQL positions, fixtures for `audit_logs`, `audit_log_archive`, comma-join and newline INSERT); B3 (tokenizer specification, depth-0, flat single-SELECT, per-statement semantics and the R3 note in D3); D5(c) dropped, D5(b) deleted, R2 interpolation claim corrected; export the three shared helpers; parse-diagnostics and empty-source error paths; prefilter; case/quote rule; test layout; table-driven fixtures. Engineering's tokenizer estimate (about 150 lines) is accepted and drives the effort bound below.

**Adopted from Security:** B-2 in full except cross-file resolution (case-insensitive; same-file constant substitution before detection; positive SQL-looking trigger for table-position substitutions and concat; tripwire; extra verbs; imported fragments handled by definition-site detection, see D5); B-3 (tokenizer, positive grammar, fixtures; alias binding removed by the single-table rule); B-1 as a caller check (D4c); P-4 as a required scope conjunct (D4b.5); P-1 (`topic.config_` prefix); F-1; package-list assertion and extension assertion; standing no-skip assertion; statement count and structural class separation for admin-only abuse; spec wording; D-5 wording ("mitigates, with named residual").

**Rejected, with reason:**
- *Cross-file one-hop resolution of imported SQL constants.* More machinery than the risk justifies; definition-site detection fails closed for every fragment that spells `audit_log`.
- *`guardedBy` / mechanical admin-guard check on `admin-only` reasons.* A string search for `application_admin` matches comments and proves nothing; a real check is route-level analysis. The caller check removes the part of the problem a static test can decide. Recorded in limits.
- *Statement fingerprint for `admin-only`.* Churns on every legitimate edit; statement count catches the abuse that matters.
- *Global-reader flag for `exact-match`.* No such reader exists; unclassifiable-fails is the safe default.
- *JOINs in `exact-match`.* Removes alias-binding ambiguity by construction; first JOIN reader gets a reviewed grammar extension.

**Deferred (all folded into the single follow-up issue, see proposal):** migration view/function scan (B-4); protected-set drift test against emitted operations (P-2); column-level check and the widened scope-level review for non-admin readers (P-3); `__tests__`-hiding assertion (B-5); a real mechanical admin-guard check. One bundled issue rather than five, per the executive review's backlog concern; Security's condition that these not live only in a header note is met by the issue.

**Open decision, not resolved by this design:** CODEOWNERS. Security asks for a one-line entry now. It needs a team handle, which no document in the repo names, and I cannot invent one. It is recorded as an open decision for the product owner (owner: Brian Surratt as repository owner, to name a handle or accept the limit). Until decided, approval is by convention and the header and spec say so. This is a real, unresolved gap in the gate, not a limit I consider accepted.

**Effort bound revised:** the tokenizer, grammar, caller check and about 40 to 50 fixtures put this at roughly three days including review, up from "about two". Past four, scope has drifted. This exceeds the figure the executive review accepted; the increase is security-driven (grammar, caller check) and is called out in the proposal for the executive to confirm.
