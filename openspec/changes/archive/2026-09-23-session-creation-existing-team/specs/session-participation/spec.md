## REMOVED Requirements

### Requirement: Facilitator-from-another-team enforcement at session setup

**Reason:** This requirement was added as a first-entry stub during the `join-team-invite-link` change, before any session-setup capability existed, specifically so the constraint could not be missed once session setup was designed. That capability now exists (`session-creation`, introduced by this change), and the enforcement point this requirement describes — the session setup endpoint — is that capability's actual endpoint (`POST /api/v1/teams/:teamId/sessions/draft`). Keeping the requirement here as well would leave the same constraint documented in two places with no single source of truth, and this stub's own purpose text says it exists only until the real feature is designed.

**Migration:** The full requirement text, plus concrete enforcement details and test scenarios this change adds (the exact endpoint, the distinguishable rejection messages, the removed-membership re-eligibility case, and the direct-API-bypass case), moves to the `session-creation` capability under "Requirement: Facilitator-from-another-team enforcement at session creation." This also resolves an ambiguity in the original stub, which did not distinguish active from historical membership: the stub's wording ("any `team_memberships` row") would have permanently disqualified a previously-removed member from ever facilitating that team again, while the new capability narrows this to an *active* row (`removed_at IS NULL`), making a previously-removed member eligible again. This is a deliberate interpretive decision, not a pure elaboration of the same rule — it matches how membership is checked everywhere else in the codebase, and nothing in the requirements ever asked for permanent disqualification. The Engineering Manager non-participation requirement and the mid-session-arrival requirement elsewhere in this spec are unaffected and remain in `session-participation`.
