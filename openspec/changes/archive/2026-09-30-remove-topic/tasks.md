## 4. Last-active-topic guard

## 5. Open-action-item confirmation flow and the archive transaction

- [x] 5.1 Inside the same transaction as Task 4.1 (after the last-active-topic guard passes, before `COMMIT`), if the request does not include `confirm=true`, call the Task 2.1 helper. If it returns one or more open action items, `ROLLBACK` and respond `200 OK` with `requiresConfirmation: true`, `reason: 'openActionItems'`, `openActionItemCount`, and `openActionItems` (the full list from Task 2.1) — do not archive the topic. If it returns zero open action items, proceed to Task 5.3 with a known `openActionItemCount` of `0` for the audit write.
- [x] 5.2 If the request includes `confirm=true`, do **not** read or trust any client-supplied count or list — call the Task 2.1 helper again inside the transaction to independently re-derive the current open-action-item count (design.md Decision 5, corrected per Marcus Oyelaran's engineer review, Finding 2). This re-derivation does **not** gate the outcome — proceed to the archive `UPDATE` (Task 5.3) regardless of the count returned — but the freshly re-derived count is **not discarded**: pass it to Task 5.3/6.1 to be written into the success audit row's `metadata`, so the re-derivation the server performs is an observable record, not inert work done and thrown away inside the lock-held transaction.
- [x] 5.3 Implement the archive `UPDATE`: `UPDATE topics SET status = 'archived', archived_at = now(), archived_by = $actor WHERE id = $topicId AND team_id = $teamId AND status = 'active'` (design.md Decision 3's SQL block). In the same transaction, write the Task 6.1 success-audit row, including the `openActionItemCount` determined by Task 5.1 (immediate-archive path) or Task 5.2 (`confirm=true` path). `COMMIT`. Respond `200 OK` with `{ topicId, status: 'archived', archivedAt }`.
- [x] 5.4 Apply `applyTimingFloor(startTime)` before both `200` outcomes (the `requiresConfirmation` response and the success response) — neither is exempt from the timing-floor requirement (design.md Decision 2's amendment).
- [x] 5.5 Write tests for `specs/remove-topic/spec.md`'s open-action-item requirement: a topic with open items returns `requiresConfirmation` without archiving; a topic with zero open items archives immediately; a `confirm=true` request archives regardless of the current open-item count; and the staleness scenario — an item resolved between the first (unconfirmed) and second (`confirm=true`) request does not block or alter the successful archive.
