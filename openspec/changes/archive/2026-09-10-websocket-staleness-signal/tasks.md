## 1. Shared Connection-Health Module (Core State Machine)

**Depends on: Group 0 (close-code constants must exist as shared symbols before tasks 1.4, 1.9, 1.10, 1.11, 1.12, and 1.14 can reference them as importable shared symbols, not re-declared literals). Everything else in this change consumes this module (design.md Decision D1/D6).**

- [x] 1.1 Create `packages/frontend/src/realtime/connectionHealth.ts`, exporting `type ConnectionHealthState = "connected" | "unknown-reconnecting" | "reauth-required"` and `useConnectionHealth(connect: () => WebSocket)`. Header comment names both issue #33 and issue #32 explicitly as required consumers, not forkers, of this module (design.md Decision D6, mirroring `staleness-signal.ts`'s header-comment convention).
- [x] 1.1a **WebSocket test double (design.md Decision D1f):** build `FakeWebSocket` in `packages/frontend/src/realtime/__tests__/fake-websocket.ts`, implementing the surface `connectionHealth.ts` touches (`addEventListener`/`removeEventListener`, `close()`, `readyState`, `CONNECTING`/`OPEN`/`CLOSING`/`CLOSED` constants) plus test-only methods to synthesize `open`/`close`/`error`/`message` events. Every subsequent test task in this group (1.4, 1.6, 1.6a, 1.7, 1.8, 1.11–1.15) is built against this double, not jsdom's native `WebSocket` (confirmed by spike to be a real network client, unsuitable as a deterministic double).
- [x] 1.1b **`connect` captured by ref, not re-invoked on identity change (design.md Decision D1d):** the hook stores the latest `connect` in a `useRef`, and the setup effect owning the socket lifecycle has an empty dependency array, reading `connect` through the ref at call time. Test: mount with a fresh `connect` closure supplied on every re-render; assert no teardown/reconnect occurs as a result of `connect`'s identity changing alone.
- [x] 1.1c **Message-stream ownership via `addEventListener`, not `.onmessage =` (design.md Decision D1e):** the hook's reauth-detection and any other internal message inspection attach via `socket.addEventListener("message", ...)`. Test: attach a second, independent `addEventListener("message", ...)` to the hook's returned socket; assert both the hook's own handling and the second listener each receive every message.
- [x] 1.1d **Unmount and teardown contract (design.md Decision D1g):** cleanup unconditionally closes the live/in-flight socket and clears both the pending retry timer and the pending timing-floor timer. Two tests: (a) unmount mid-retry-loop — assert no further reconnect attempt or state update after unmount; (b) React 18 StrictMode double-invoke (mount → cleanup → mount rapidly) — assert exactly one live socket exists at the end.
- [x] 1.2 Enforce no fourth state: every `switch` on `ConnectionHealthState` (in the hook, in `ConnectionStatusBanner`, in the grid-marker component) includes a `default: { const _exhaustive: never = state; ... }` block, matching the established convention in `packages/backend/src/realtime/ws-event-dispatcher.ts:81-88` (design.md Decision D1, corrected per Engineer design review finding 2 — a `switch` with no `default` case does NOT fail to compile on a missing case; the `never` assignment inside `default` is the actual guard). Compile-time regression test: a fixture that widens the union to a fourth value and asserts (via `// @ts-expect-error` or equivalent) that exactly this `never` assignment is what fails to compile.
- [x] 1.3 Implement `computeRetryDelay(attempt: number): number` as a pure function taking only the attempt count — full-jitter exponential backoff, `min(30000, 1000 * 2^attempt)` upper bound, uniform draw from `[0, upperBound)` (design.md Decision D2). No branch anywhere in this function or its caller reads `event.code` or any connection-attempt outcome type. This function is reachable only from the `unknown-reconnecting` path, never from `reauth-required` (task 1.10). Jitter source is `Math.random()` exclusively — no `rng`/seed parameter is added to the signature (design.md Decision D2).
- [x] 1.4 **Retry-symmetry test (proposal.md acceptance condition, spec.md scenario "A revoked connection and a flaky connection produce identical retry timing"):** force a `STALE_SIGNAL_CLOSE_CODE` close and, separately, a simulated raw network close/error, through the same `useConnectionHealth` handler; assert identical retry count, backoff schedule, and jitter draw sequence via `vi.spyOn(Math, "random")` for determinism, for both.
- [x] 1.5 Add `STALENESS_TIMING_FLOOR_MS = 2000` as a module-local constant (design.md Decision D3) — not read from `process.env`, a config file, or any feature-flag surface. Wire it into `useConnectionHealth` so the reported `state` does not flip to `"unknown-reconnecting"` until at least this long after the triggering close/error event. The floor does not apply to `reauth-required` (task 1.10) — that transition is not ambiguous the way a close/error event is, so there is no cause-leak reason to delay it.
- [x] 1.6 **Timing-floor test:** an instantly-rejected subscription attempt does not surface `"unknown-reconnecting"` before the floor elapses; a slower-failing network drop is held to the identical floor via the identical code path (spec.md "An instantly-failing rejected subscription does not render before the floor elapses" / "The floor applies identically to a slower-failing network drop").
- [x] 1.6a **Early-recovery race test (design.md Decision D3a):** a connection fails, the floor timer starts, and the connection reconnects successfully *before* the floor elapses — assert `state` remains `"connected"` throughout and is never observed as `"unknown-reconnecting"` for this episode.
- [x] 1.7 **Initial-connection-failure bucketing test (design.md Decision D5):** a rejected first-ever subscription attempt (no prior successful connection) drives `state` to `"unknown-reconnecting"` via the same code path, same timing floor, and same retry function as a mid-session drop — assert no separate internal branch or state exists for "never connected" vs. "lost connection."
- [x] 1.8 **Silent-recovery test (design.md Decision D4):** transitioning from `"unknown-reconnecting"` back to `"connected"` produces no event, callback, or flag beyond the state value itself changing — assert no additional signal is observable to a consumer.
- [x] 1.9 Code-review checklist item, backed by a grep-based regression test: no reference to `STALE_SIGNAL_CLOSE_CODE`, `.code ===`, or any close-code/outcome-type comparison exists anywhere in `connectionHealth.ts` or its retry/render call sites, **except** the single, named `REAUTH_GRACE_EXPIRED_CLOSE_CODE` check that routes to `reauth-required` (task 1.10, design.md Decision D1a) — the grep/review rule allows exactly this one exception and no other close-code or outcome-type comparison. The grep is extended (Security design review finding 5) to also flag any `console.*` call within `connectionHealth.ts` that references `event.code`, `event.reason`, or the parsed message body — a debugging leftover that prints cause information to the console would violate the same invariant in spirit even though it wouldn't fail the branching check or any rendered-output test.
- [x] 1.10 **`reauth-required` detection (design.md Decision D1a):** wire `useConnectionHealth` to recognize the in-band `{"eventType": "reauth_required"}` message, narrowed against the shared `WsClientMessage` type (`@dipstick/shared`), and, as a fallback, a raw close with `REAUTH_GRACE_EXPIRED_CLOSE_CODE` (4001, imported from `@dipstick/shared` per task 0.1), transitioning `state` to `"reauth-required"` from either. This path bypasses the timing floor (task 1.5) and never calls `computeRetryDelay` (task 1.3) or enters the retry loop.
- [x] 1.10a **Sticky-state guard implementation (design.md Decision D1c):** on transition into `"reauth-required"` (via either signal recognized by task 1.10), synchronously clear any pending retry `setTimeout` before it can fire. In the close/error handler, check `state === "reauth-required"` first — before any other close/error branching — and return immediately for any subsequent close/error of any code, including the socket's own expected 4001 close arriving after the message already transitioned state. No `connect()` call is made by this hook instance once `"reauth-required"` is entered. This is the implementation task 1.14 and 1.15 test against.
- [x] 1.11 **`reauth-required` no-retry test (proposal.md acceptance condition, spec.md scenario "A 4001 close or a `reauth_required` message never enters the retry path"):** force a `REAUTH_GRACE_EXPIRED_CLOSE_CODE` close and, separately, a `reauth_required` message, through the same `useConnectionHealth` handler; assert `state` becomes `"reauth-required"` in both cases, `computeRetryDelay` is called zero times, and `connect()` is not called again as a result of this transition.
- [x] 1.12 **No-fallthrough test:** assert `"reauth-required"` is never reached via a `STALE_SIGNAL_CLOSE_CODE` close or a raw network close/error, and `"unknown-reconnecting"` is never reached via a `reauth_required` message or a `REAUTH_GRACE_EXPIRED_CLOSE_CODE` close — the two paths do not merge.
- [x] 1.13 **`reauth-required` sub-cause-blindness test:** assert `useConnectionHealth` exposes no information distinguishing why the SEC-26 refresh failed (retry-budget exhaustion vs. definitive revocation vs. concurrent session destruction) beyond the single `"reauth-required"` state value, matching the reauth spec's own non-disclosure of that sub-cause.
- [x] 1.14 **Race A test — late close after `reauth-required` already entered (design.md Decision D1c, Security design review finding 1, blocking):** test task for 1.10a's entry guard. Force a `reauth_required` message, then a subsequent close event carrying `STALE_SIGNAL_CLOSE_CODE`, through the same handler; assert `state` remains `"reauth-required"` and is never observed reverting to `"unknown-reconnecting"`.
- [x] 1.15 **Race B test — stale pending retry timer cleared on entry to `reauth-required` (design.md Decision D1c, Security design review finding 1, blocking):** test task for 1.10a's synchronous timer-clear. Put the hook into `"unknown-reconnecting"` with a retry timer pending, then deliver a `reauth_required` signal before that timer fires; assert the pending timer is cancelled synchronously and `connect()` is never called again by this hook instance.
