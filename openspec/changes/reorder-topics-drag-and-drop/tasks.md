## 2. Drag hook

- [ ] 2.1 Test infrastructure: add a `PointerEvent` polyfill and `setPointerCapture`/`releasePointerCapture`/`hasPointerCapture` stubs to the frontend vitest setup (none exist today), and a helper to mock `getBoundingClientRect` on rows. Exit condition: the full frontend suite runs unchanged and green with the new setup, before any hook test is written.
- [ ] 2.2 Define and type the `useTopicDrag` interface first (in the hook file, before the body), and review it against 3.x. Constants named in the file: `DRAG_THRESHOLD_PX` (5), `DRAG_HANDLE_MIN_PX` (24), `DRAG_DIM_OPACITY` (0.5).
  - Input: `{ enabled: boolean, onDrop(topicId, slot, rowCount), onCancel(topicId) }`. `onDrop` is read through a ref (latest-callback). `slot` is 0..N, never the final index; `rowCount` is the number of rows the hook measured, so the page can validate it against N.
  - Output state for rendering: `draggedTopicId: string | null`, `dropSlot: number | null` (changes only when the slot value changes), `isDragging: boolean` (true once past the threshold).
  - Wiring: `containerRef` (the list element, for outside-release hit-testing and `user-select: none`), `registerRow(topicId)` (ref callback, for measurement), and `getHandleProps(topicId)` (pointerdown handler, `touch-action: none`, the handle's DOM ref) so the page attaches the hook to each handle.
  - Control: imperative `cancel()`, idempotent. Cancel rule: **every cancel except unmount calls `onCancel(topicId)`**, including `enabled` going false while a drag is active (the hook cancels internally) and an imperative `cancel()`. Unmount calls neither callback. The page therefore has exactly one place for cancel focus (`onCancel`, task 3.4).
- [ ] 2.3 Implement `useTopicDrag` in its own file to that interface: primary-button pointerdown on the handle, threshold, midpoint hit-testing via `computeDropSlot`, `touch-action: none` on the handle only, cancel on Escape, `pointercancel`/lost capture, window blur, `contextmenu`, release outside the list container bounds. No auto-scroll. No live region, no focus handling, no keyboard sensor. Follows the listener contract in design.md Decision 1: `setPointerCapture` in try/catch (failure means no drag), one stored `pointerId`, per-move and on-scroll `getBoundingClientRect()` measurement, fresh rects at pointerup, self hit-test of the list rect on release, `user-select: none` on the list while dragging, and every transient listener removed on every exit path. The Escape listener does not `preventDefault` or `stopPropagation`, and exists only while a drag is active, so a dialog open at that moment still receives its own Escape. No `console` output.
- [ ] 2.4 Hook state-machine tests with `fireEvent.pointer*` (written alongside 2.3): idle to pending to dragging to idle; threshold crossing; secondary button and second pointer ignored; each cancel cause (Escape, pointercancel, lostpointercapture, blur, contextmenu, release outside the list rect, `setPointerCapture` throwing) calls `onCancel(topicId)` once; `enabled` going false mid-drag cancels and calls `onCancel`; imperative `cancel()` calls `onCancel` and is idempotent; `onDrop` carries `(topicId, slot, rowCount)`; `user-select: none` on the container while dragging and cleared on every exit; unmount mid-drag removes every listener, calls `releasePointerCapture`, clears `user-select` and calls neither callback; no re-render of the consumer on a `pointermove` that does not change the slot; a 30-row smoke case (drag still works above the 25-topic assumption); an Escape pressed while a dialog is open is not consumed (assert `defaultPrevented` is false and the event reaches a listener on the dialog). R-THRESHOLD, R-UNMOUNT, R-CANCEL (hook level), R-BUTTON-ONLY.
