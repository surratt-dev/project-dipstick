# Engineering Health Check — Summary

## What It Is

A recurring, facilitated retrospective where engineers vote on subjective topics related to their development experience and codebase health. Results are tracked over time to surface trends and prompt discussion.

## Key Characteristics

- **Duration:** ~30 minutes (first session: 1 hour); brief by design
- **Cadence:** Biweekly to start; adjust as team tempo changes
- **Participants:** All engineers on the team
- **Facilitator:** A senior engineer from *another* team — empathetic, a good listener, not in the team's reporting chain

## How It Works

1. Facilitator presents each topic; participants vote simultaneously (finger vote 1–4, or Roman up/down/sideways)
2. Facilitator records results in a spreadsheet; tracks averages and tallies over time
3. Outliers or significant changes from trend prompt brief discussion — not debate
4. Issues identified become action items for a senior team engineer to address later; problems are not solved in the session

## Topics Covered

| Category | Topics |
|---|---|
| Developing & Changing Code | Ease of adding features, reasoning about code, quality of code under active development, overall project code quality |
| Automated Tests | Test suite effectiveness, consistency (flakiness), quality of tests under active development, overall test suite quality, test suite run time (recorded only) |
| Other | Pipeline confidence, comfort with the tech stack, pairing effectiveness |
| Overall | Project trend (up / steady / down) |

## Why It Matters

- Gives engineers a dedicated, low-pressure space to surface frustrations that often go unspoken
- Separating from the keyboard creates objectivity difficult to achieve while heads-down in an IDE
- Team discussion builds shared understanding and consensus around engineering pain points

## Tips

- Customize topics to fit your team's context
- Track action items across sessions and follow up on their effectiveness
- Use a small, cozy room to encourage open conversation
- Teams may apply the health check to greenfield code only, or legacy code as well — team decides
